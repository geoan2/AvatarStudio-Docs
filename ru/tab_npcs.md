# Вкладка 5: NPC (NPCs)

**NPC система Avatar Studio QS** — это не просто "таблица с данными". Это **фабрика персонажей**, которая за **три клика мыши** создает полностью функционального NPC или главного героя с анимацией, логикой и поведением.

То, на что в обычном Unreal уходят **часы ручной работы**, здесь делается **автоматически**.

[СКРИНШОТ: Вкладка NPCs с деревом ассетов и кнопкой "Create Character"]

---

## 1. Философия: Data Table + Автогенерация

Вместо создания отдельного Blueprint для каждого NPC, мы используем **NPC Data Table** — таблицу, где каждая строка = один персонаж.

### Но это не просто таблица!
При создании новой строки система **автоматически генерирует**:
*   ✅ **Animation Blueprint** с готовой логикой.
*   ✅ **BlendSpace1D** для плавного перехода между Idle/Walk/Run/Sprint.
*   ✅ **State Machine** с состояниями Locomotion, Jump Start, Jump Fall, Jump Land.
*   ✅ **Control Rig** для IK (ноги адаптируются к рельефу).
*   ✅ **Морфинг лица** (готовые морф-таргеты для эмоций и речи).
*   ✅ **Блуждающий взгляд** (NPC не смотрит в одну точку).
*   ✅ **Система внимания** (для ГГ — автофокус на интерактивных объектах).

---

## 2. Автогенерация Animation Blueprint — 🔥 KILLER FEATURE

### Сколько времени нужно в обычном Unreal?
*   Создать Animation Blueprint вручную: **5 минут**.
*   Настроить BlendSpace (Idle/Walk/Run): **10 минут**.
*   Создать State Machine с переходами: **20 минут**.
*   Настроить Control Rig для IK: **15 минут**.
*   Добавить логику прыжков: **10 минут**.
*   **ИТОГО: ~1 час работы.**

### Сколько времени нужно в Avatar Studio QS?
*   Нажать кнопку **"Create Character"**: **1 секунда**.
*   Выбрать анимации (Idle, Walk, Run): **30 секунд**.
*   Нажать **"Generate"**: **1 секунда**.
*   **ИТОГО: ~32 секунды.**

### Что создается автоматически:

#### 1. **BlendSpace1D (Locomotion)**
*   Плавный переход между анимациями:
    *   `Idle` (скорость 0).
    *   `Walk` (скорость 150).
    *   `Run` (скорость 300).
    *   `Sprint` (скорость 600, опционально).
*   Настроенная ось скорости.
*   Автоматическая интерполяция между анимациями.

#### 2. **State Machine (Main States)**
*   **Locomotion** — Основное движение (использует BlendSpace).
*   **Jump Start** — Начало прыжка.
*   **Jump Fall** — Полет/падение.
*   **Jump Land** — Приземление.
*   **Переходы** между состояниями с готовыми условиями:
    *   `Locomotion → Jump Start` — Если нажата кнопка прыжка.
    *   `Jump Start → Jump Fall` — Когда анимация старта закончилась.
    *   `Jump Fall → Jump Land` — Когда персонаж коснулся земли.
    *   `Jump Land → Locomotion` — Когда анимация приземления закончилась.

#### 3. **Control Rig (IK для ног)**
*   Автоматическая трассировка лучей от стоп к земле.
*   Адаптация ног к рельефу (лестницы, склоны, неровности).
*   Настроенные параметры для плавной работы.

#### 4. **Event Graph (Логика)**
*   Готовые переменные для скорости, прыжка, состояния в воздухе.
*   Связь с Character Movement Component.

## 3. Морфинг лица (Facial Morphing)

Каждый созданный персонаж автоматически получает **готовые морф-таргеты** для:
*   **Речь** — Виземы (v_Ah, v_F, v_O, v_M и т.д.).
*   **Эмоции** — Улыбка, грусть, удивление, гнев.
*   **Моргание** — Автоматическое и ручное.

Эти морф-таргеты **автоматически связываются** с системой Lipsync, и персонаж **сразу готов** к озвученным диалогам.

## 4. Система взгляда (Gaze System) — 🔥 KILLER FEATURE

Каждый созданный персонаж автоматически получает **компонент `UAS_QS_LookAtControllerComponent`** — одну из самых сложных и впечатляющих систем плагина.

### Почему это важно?
В обычных играх NPC смотрят в одну точку, как манекены. **Gaze System** делает персонажей **живыми**:
*   Глаза двигаются естественно
*   Голова поворачивается к интересным объектам
*   В диалоге персонаж смотрит на собеседника
*   Игрок автоматически фокусируется на врагах и интерактивных объектах

---

### A. Блуждающий взгляд (Ambient Gaze)

Когда у NPC нет конкретной цели, он не смотрит в одну точку. Система генерирует **случайные точки для созерцания** в пространстве вокруг персонажа.

#### Зонирование (3 зоны)

Система делит пространство на **3 зоны** с разными характеристиками:

##### 1. **Comfort Zone (Комфортная зона)**
*   **Углы**: ±24° по горизонтали, ±16° по вертикали
*   **Длительность**: 1.2–3.0 секунды
*   **Вес**: 60% точек
*   **Описание**: Персонаж смотрит прямо перед собой, слегка вниз (естественная поза покоя)

##### 2. **Normal Zone (Нормальная зона)**
*   **Углы**: ±40° по горизонтали, ±25° по вертикали
*   **Длительность**: 3.0–5.4 секунды
*   **Вес**: 30% точек
*   **Описание**: Умеренные отклонения (осмотр окружения)

##### 3. **Extreme Zone (Экстремальная зона)**
*   **Углы**: ±50° по горизонтали, ±35° по вертикали
*   **Длительность**: 5.4–9.6 секунды
*   **Вес**: 10% точек
*   **Описание**: Большие углы (персонаж заметил что-то интересное сбоку или сверху)

#### Настройки
*   **Ambient Frequency** (0-100%) — Как часто персонаж смотрит по сторонам
    *   100% = Постоянно разглядывает окружение
    *   50% = Половину времени смотрит прямо
    *   0% = Всегда смотрит прямо перед собой
*   **Num Ambient Gaze Points** — Количество точек для созерцания (по умолчанию 8)

---

### B. Автоматический поиск целей (Auto Targeting) — для NPC

NPC автоматически ищет **интересные объекты** вокруг себя и смотрит на них.

#### Как это работает:
1.  **Сфера восприятия** — Вокруг NPC создается невидимая сфера (радиус настраивается)
2.  **Обнаружение целей** — Когда актор входит в сферу, система проверяет:
    *   Есть ли у него интерфейс `IAS_QS_LookAtInterface`?
    *   Какой у него приоритет?
3.  **Выбор лучшей цели** — Система выбирает цель с наивысшим приоритетом
4.  **Фокусировка** — NPC смотрит на цель в течение случайного времени (3–4.5 сек)
5.  **Кулдаун** — После того как NPC посмотрел на цель, она помещается в кулдаун (20 сек)

#### Приоритеты:
*   **Player Character** — 100 (наивысший приоритет)
*   **Default NPC** — 80
*   **Other Objects** — Зависит от компонента `UAS_QS_GazeTargetComponent`

#### Настройки:
*   **bEnableAutoTargeting** — Включить автоматический поиск целей
*   **Interest Responsiveness** (0-100%) — Шанс, что NPC отреагирует на найденный объект
    *   100% = Реагирует всегда
    *   10% = Очень редко обращает внимание
*   **Default Gaze Duration Range** — Как долго NPC смотрит на цель (3.0–4.5 сек)
*   **Target Interest Cooldown** — Время кулдауна для цели (20 сек)

---

### C. Режим диалога (Dialogue Mode)

Когда NPC входит в диалог, система автоматически переключается в **режим диалога**.

#### Что происходит:
1.  **Фокусировка на собеседнике** — NPC смотрит на собеседника
2.  **Микродвижения головы** — Небольшие случайные отклонения (±5°) для живости
3.  **Плавные переходы** — Голова плавно поворачивается к новой точке

#### Настройки:
*   **bAllowMicroMovementsInDialogue** — Включить микродвижения
*   **Dialogue Micro Movement Angle** — Максимальный угол отклонения (5°)
*   **Dialogue Micro Movement Speed** — Скорость интерполяции (0.5)
*   **Dialogue Micro Movement Interval** — Интервал между микродвижениями (1.5–3.5 сек)

#### Активация:
```cpp
// Войти в режим диалога
LookAtController->EnterDialogueState(DialoguePartner, true);

// Выйти из режима диалога
LookAtController->ExitDialogueState();
```

---

### D. Режимы игрока (Player Modes) — для Player Character

Если персонаж управляется игроком (`bIsPlayerControlled = true`), система работает по-другому.

#### Режимы:

##### 1. **Limited Mode (Ограниченный)**
*   **Когда**: Игрок активно управляет персонажем
*   **Углы**: ±15° по горизонтали, ±10° по вертикали
*   **Описание**: Ненавязчивые движения головы (не мешают игроку)

##### 2. **Full Mode (Полный)**
*   **Когда**: Игрок бездействует >5 секунд
*   **Углы**: Как у NPC (все 3 зоны)
*   **Описание**: Полноценный блуждающий взгляд (персонаж "оживает" при бездействии)

##### 3. **Combat Mode (Боевой)**
*   **Когда**: Игрок нацелился на врага
*   **Описание**: Жесткая фокусировка на враге (голова следует за целью)

##### 4. **Interact Mode (Взаимодействие)**
*   **Когда**: Игрок навел прицел на интерактивный объект
*   **Описание**: Жесткая фокусировка на объекте (дверь, сундук, NPC)

#### Настройки:
*   **Idle State Threshold** — Время бездействия для перехода в Full Mode (5 сек)
*   **Player Limited Yaw Angle** — Угол по горизонтали для Limited Mode (15°)
*   **Player Limited Pitch Angle** — Угол по вертикали для Limited Mode (10°)

#### Активация:
```cpp
// Сообщить системе, что персонажем управляет игрок
LookAtController->SetPlayerControlState(true);

// Сбросить таймер бездействия (при любом вводе)
LookAtController->UpdatePlayerLastInputTime();

// Установить цель высокого приоритета (враг)
LookAtController->SetHighPriorityTarget(Enemy, EPlayerGazeMode::Combat);

// Снять цель высокого приоритета
LookAtController->ClearHighPriorityTarget(EPlayerGazeMode::Combat);
```

### E. Обработка поворотов тела

Система автоматически обрабатывает **резкие повороты тела**, чтобы голова не "отрывалась" от тела.

#### Как это работает:
1.  **Детекция поворота** — Система отслеживает угловую скорость тела
2.  **Заморозка головы** — Если скорость >180°/сек, голова "замораживается" в текущем направлении (относительно мира)
3.  **Разморозка** — Когда поворот завершен, голова плавно возвращается к цели (задержка 0.2 сек)

#### Настройки:
*   **Sharp Turn Threshold** — Порог угловой скорости для детекции (180°/сек)
*   **Unfreeze Delay** — Задержка перед разморозкой (0.2 сек)

---

### F. Общие настройки

#### Скорости интерполяции:
*   **Look At Direction Interpolation Speed** — Скорость поворота головы к цели (6.0)
*   **Look At Alpha Interpolation Speed** — Скорость включения/выключения взгляда (5.0)

#### Ограничения:
*   **Max Look At Distance** — Максимальное расстояние до цели (500 см)
*   **Max Look At Angle** — Максимальный угол поворота головы (64°)

#### Другое:
*   **Gaze Source Socket Name** — Имя сокета, откуда NPC смотрит (`head`)
*   **bRequireInterface** — Требовать интерфейс `IAS_QS_LookAtInterface` для целей

---

### G. Интеграция с Animation Blueprint

Система автоматически обновляет переменные в Animation Blueprint:
*   **LookAtDirection** — Направление взгляда (вектор)
*   **LookAtAlpha** — Сила взгляда (0.0–1.0)

Эти переменные используются в **Control Rig** для поворота головы и глаз.

---

### H. Пример конфигурации

#### Для NPC (охранник):
*   `bEnableLookAtSystem = true`
*   `bEnableAutoTargeting = true` — Ищет игрока и других NPC
*   `bEnableAmbientLook = true` — Блуждающий взгляд
*   `Ambient Frequency = 80%` — Часто смотрит по сторонам
*   `Interest Responsiveness = 100%` — Всегда реагирует на игрока

#### Для Player Character:
*   `bEnableLookAtSystem = true`
*   `bEnablePlayerInteractions = true` — Включить режимы игрока
*   `bEnableAmbientLook = true` — Блуждающий взгляд при бездействии
*   `Idle State Threshold = 5.0` — Переход в Full Mode через 5 сек

#### Для NPC (торговец):
*   `bEnableLookAtSystem = true`
*   `bEnableAutoTargeting = true`
*   `bEnableAmbientLook = true`
*   `Ambient Frequency = 50%` — Умеренная активность
*   `Interest Responsiveness = 60%` — Иногда игнорирует прохожих

## 6. Структура NPC Data Table

Каждая строка таблицы (`FNPCTableRow`) содержит:

### 🎭 Основные данные:
*   **NPC Actor Class** — Ссылка на Blueprint Actor персонажа (автоматически создается).
*   **Display Name** — Локализуемое имя для UI.
*   **Portrait** — Портрет для диалоговых окон.
*   **bIsPlayerCharacter** — Флаг "это главный герой" (активирует систему внимания).

### 🎤 Озвучка:
*   **Character Voice Banks** — Массив Voice Assets для этого NPC.

### 🏛️ Фракции:
*   **Faction IDs** — Массив ID фракций (для репутации).

### 🧬 Характеристики:
*   **Personality Traits** — Теги характера (`Personality.Aggressive`, `Personality.Friendly`).
*   **Race Tag** — Раса (`Race.Human`, `Race.Elf`).
*   **Gender Tag** — Пол (`Gender.Male`, `Gender.Female`).
*   **NPC Status Tag** — Статус (`Status.Alive`, `Status.Hostile`).

## 7. Workflow: Создание NPC за 3 клика

### Шаг 1: Создайте NPC Data Table
*   Нажмите **"Create NPC Asset"** во вкладке NPCs.
*   Укажите имя (например, `DT_Guards`).

### Шаг 2: Добавьте строку и нажмите "Create Character"
*   Добавьте новую строку с ID (например, `Guard_01`).
*   Нажмите кнопку **"Create Character"** (появится диалог).

### Шаг 3: Выберите анимации и сгенерируйте
*   Укажите анимации:
    *   **Idle** — Стоит на месте.
    *   **Walk** — Идет.
    *   **Run** — Бежит.
    *   **Jump Start/Fall/Land** — Прыжок (опционально).
*   Нажмите **"Generate"**.

### Результат:
Система создаст:
*   `ABP_Guard_01` — Animation Blueprint.
*   `BS_Guard_01_Locomotion` — BlendSpace.
*   `BP_Guard_01` — Actor Blueprint (если не существует).

Всё готово к использованию в игре!

## 8. Поддержка Главного Героя (Player Character)

### Флаг `bIsPlayerCharacter`:
*   Если `true`, эта строка описывает вариант протагониста.
*   Система добавляет:
    *   **Attention System** — Автофокус на интерактивных объектах.
    *   **Enhanced Input System** — 🔥 **KILLER FEATURE** — Полностью автоматическая настройка Enhanced Input!
    *   **Camera Follow** — Камера следует за персонажем.

### Enhanced Input System — Уникальная особенность!

При создании Player Character система **автоматически**:
- ✅ Создает 10 Input Actions (Move, Look, Jump, и т.д.)
- ✅ Создает Input Mapping Context с привязками клавиш
- ✅ **Программно добавляет Input Modifiers** (Swizzle, Negate)
- ✅ Настраивает автоматический fallback на Legacy Input
- ✅ **Игрок готов к игре сразу после создания!**

**Подробнее:** [Enhanced Input System](input_system.md) — полное описание этой уникальной системы

### Пример использования:
Создайте NPC Data Table `DT_PlayerCharacters` с тремя строками:
*   `Warrior` — Мужчина, класс `BP_PlayerWarrior`.
*   `Mage` — Женщина, класс `BP_PlayerMage`.
*   `Rogue` — Мужчина, класс `BP_PlayerRogue`.

В начале игры игрок выбирает одну из этих строк, и система автоматически настраивает всё.

## 9. Интеграция с другими системами

### Диалоги:
*   Узлы диалога ссылаются на NPC по **Row Name** (ID строки).
*   Система автоматически подтягивает портрет, озвучку и имя.

### Квесты:
*   Квестовые цели требуют взаимодействия с конкретным NPC (по Row Name).
*   Проверка репутации использует `Faction IDs`.

### Спавнеры:
*   Спавнеры создают NPC, загружая `NPC Actor Class` из таблицы.
*   Можно спавнить случайного NPC из списка.
